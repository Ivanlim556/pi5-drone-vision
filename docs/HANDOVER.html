1. What the system does

Camera (AR0234 since 5 Oct; CM3 as backup)→Pi 5 + Hailo-8L AI chip
YOLO finds objects, 30 fps→ VL53L5CX distance sensor
8×8 grid, up to 4 m→MAVLink to the flight controller
obstacle distances, 10×/s
  • The camera picture goes to a web page (/cam). The same picture with boxes and distances in cm goes to /detect.
  • The Pi combines each detected object with the sensor distance and sends ArduPilot an OBSTACLE_DISTANCE message: 8 slices across the 45° view in front, in cm. ArduPilot uses it to stop or slide around the obstacle.
  • Everything starts by itself at power-on (about 40 s). No keyboard or screen needed.
  • Each run writes a log (one CSV row per frame) to ~/detect/logs/.

From a Windows laptop (PowerShell)

Connect your laptop to the same WiFi as the Pi (TP-Link_C6A4), then:

ssh pi@pi5drone.local

First time: type yes, then the password. Nothing shows while you type the password; that's normal. If pi5drone.local isn't found, use the IP: ssh pi@192.168.0.110. If that fails too, find the Pi's current IP in the router's client list.

sudo commands ask for the same password.

No network at all?

Plug a screen into the Pi's HDMI 0 port (next to the USB-C power) and a USB keyboard, then log in with the same username and password.

Change the passwords once the handover is done: the Pi login with passwd; the web login in /home/pi/mediamtx/cam.yml (authInternalUsers). Then update this page.

Never stop the detector with kill or pkill. That leaves the Hailo chip locked ("Device disconnected") until a reboot. Always use systemctl.

5. Talking to the flight controller (ArduPilot)

The Pi sends three MAVLink messages, from system 1, component 196 (obstacle avoidance):

MessageRateMeaning
OBSTACLE_DISTANCE10 Hz8 slices of 5.625° from −20° (left) to +20° (right), in cm, body frame. 401 = clear to 4 m, 65535 = no data (sides/back).
HEARTBEAT1 Hz"Companion computer alive" (type 18 = onboard controller)
STATUSTEXT≤1/sWarning text such as OBSTACLE person 85cm left when something is within 1.5 m. It shows in Mission Planner's Messages tab.

Right now (no FC connected)

The Pi waits on UDP port 14550. To see what an FC would get, run on Ivan's laptop in the project folder: .\fc_view.ps1. That opens a radar window.

Bench test with the real FC: propellers OFF

  1. Connect the FC to a Pi USB port. On the Pi, ls /dev/ttyACM* should show /dev/ttyACM0.
  2. Change the line in /etc/systemd/system/pi-detect.service (use sudo nano): add --mavlink /dev/ttyACM0 to the end of the ExecStart= line. Then run sudo systemctl daemon-reload && sudo systemctl restart pi-detect.
  3. In Mission Planner, set: PRX1_TYPE = 2 (MAVLink), AVOID_ENABLE = 3, AVOID_MARGIN = 1.0, AVOID_BEHAVE = 1 (stop). Indoors also set LOIT_SPEED = 100 (1 m/s). Reboot the FC.
  4. Mission Planner → Ctrl-F → Proximity: move a hand in front of the sensor and the distance should appear in front.

For flight, use the wired UART: FC port J11 → Pi pins 8 (TX), 10 (RX), 6 (GND). This needs dtparam=uart0=on in /boot/firmware/config.txt, --mavlink /dev/ttyAMA0,921600, and on the FC SERIALn_PROTOCOL = 2, SERIALn_BAUD = 921. Which SERIALn is J11 is still unconfirmed; check with the FC firmware owner.

6. Hardware and wiring

PartNotes
Raspberry Pi 5Raspberry Pi OS (Debian trixie). Power with a 5 V 5 A USB-C PD supply; weaker supplies cause lag and random reboots.
Camera Module 3On CAM/DISP 0. CAM1 on this Pi is faulty, don't use it. The ribbon is fragile: reseat it with the power off.
AI HAT+ (Hailo-8L, 13 TOPS)On the PCIe connector. Model: /usr/share/hailo-models/yolov8s_h8l.hef
Active coolerNeeded. Without it the Pi throttles at 85 °C.
AR0234 board (in-house) — in use since 5 Oct 2026Mono, global shutter, 70° lens (M2504ZH05S 4 mm, focused at 3–5 m — don't turn it). On CAM/DISP 0. The cable's bare contacts must face the pads at both ends (blue stiffener away from the board): the wrong way round gives failed to read chip id. The distance sensor sits on the camera's right; keep them together, facing the same way. Stream: 1280×800 at 30 fps, ~0.18 s delay. Its driver has a small local patch (ar0234-force-mono.patch) — after any apt upgrade that updates ar0234-rpi-dkms or the kernel, re-apply it (guide 2.0 box / GitHub README).

VL53L5CX-SATEL → Pi header

Sensor pinPi pinSensor pinPi pin
GND6SCL5

I²C bus 1, address 0x29. Peel off the protective film. Mounting: the sensor sits 9.5 cm beside the lens, both upright and facing straight ahead, parallel. The detector corrects for that gap (setting --tof-baseline 0.095); if you move the sensor, change it to the new gap in metres. Keep everything on one rigid base and tape the cables near each connector — loose cables disconnect.

7. When something breaks

SymptomLikely cause → fix
Can't sshLaptop on a different WiFi, or the Pi hasn't booted (wait 1 min). Try the IP instead of .local. Last resort: HDMI + keyboard.
Web page lags or freezesWeak power supply → use the 5 A PD supply. Check vcgencmd get_throttled.
AR0234: no picture, failed to read chip idCable the wrong way round or not seated. Power off, check the contacts face the pads at both ends, reseat.
AR0234: purple-tinted pictureThe mono fix is missing: cat /sys/module/ar0234/parameters/force_mono must say Y — re-apply the patch (see above).
No picture; log says frontend has timed outCamera ribbon loose. Power off, reseat both ends (CAM0), and don't move the camera while it's running.
Boxes but no distancesSensor frozen. The software power-cycles it by itself within 3 s. If it stays dead: pinctrl get 2,3 should show hi for both. If SDA is lo, power off and reseat the SDA wire (pin 3).
Log says Device disconnected (Hailo)Someone used kill. Run sudo reboot.
Box shows the wall's distance, not the object's; squares too high/lowThe sensor moved or leans: stand it upright, parallel to the lens, at the gap set in --tof-baseline (9.5 cm now).
Distances look mirrored (obstacle on the wrong side)The sensor was turned. Add --tof-flip ud (or lr, udlr) to the ExecStart= line of the service file. The default is udlr.
Wrong date in log namesNormal: the Pi has no clock battery. Logs are numbered (0087_…); trust the t_s column.

9. Handover status: what's done, what's left for the team

Ivan's part was the Pi side: camera → detection → distance → MAVLink obstacle reports to the FC. That part is finished and tested on the bench (GitHub release v2.0-ar0234). The avoidance itself (ArduPilot settings, flying) is the FC team's part.

Done (Sep–Oct 2026)

  • AR0234 camera board designed, made (JLCPCB) and working: 1280×800 at 30 fps, ~0.18 s delay, mono fix in the driver. Design files on GitHub: hardware/ar0234-board/.
  • Detection on the Hailo-8L: YOLOv8s at 30 fps, starts by itself at power-on.
  • Distance sensor VL53L5CX: maximum error 6 cm (to 1 m), aligned to the AR0234; 0 freezes in 77 h since I²C was lowered to 100 kHz.
  • Obstacle reports to the FC (MAVLink OBSTACLE_DISTANCE ~10/s + heartbeat + warnings), checked live with the laptop stand-in fc_view.ps1.
  • CM3 kept as a backup: sudo camera cm3 && sudo reboot switches everything back.
  • Logs, watchdogs, auto-restart; full guide, build log and this page.
